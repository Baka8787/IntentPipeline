01

兩條單向管道：執行期零方法呼叫

單寫多讀 ／ 單寫單讀

Rig 與 Controller 之間沒有任何方法呼叫、事件或回呼，只有兩份共享資料各自單向流動。 每條箭頭標了五件事：資料是什麼、誰是唯一 Writer、座標空間、更新時機、以及是不是跨幀。

箭頭資料唯一 Writer座標空間跨幀？
Animator → PoseDataIK goal 位置＋旋轉、Avatar 常數FootIKRig世界❌ 每幀整組覆寫
PoseData → Controller同上，唯讀—世界本幀新鮮值
PoseData → FootstepDetector同一份引用—世界偵測器自持 tracker
黑板 → ControllerIsGrounded、BlockIKMotionDriver／ArbiterPipeline—⚠️ 讀到的是上一幀 Move() 之後
root → Controllertransform.position.yMotionDriver世界順序 6 已更新 ⇒ 本幀新位置
場景 → ControllerRaycast 命中點與法線Unity Physics世界❌ 不快取、不濾波
Controller → TargetData位置／旋轉／權重 ×2 ＋ PelvisOffsetYFootIKController世界✅ 權重與骨盆是跨幀的
TargetData → Rig同上，唯讀—世界下一幀才套用
02

三個「接地」不是同一個 authority

本子系統最重要的一節

三個東西聽起來都在講「腳有沒有踩到地」，但它們是三個不同的權威，服務三個不同的問題， 而且可以互相矛盾——那是正常的。把它們混成一件事，是這個子系統最貴的誤解。

看起來像 bug 的現象真正原因屬於哪一層
起跳那一幀腳突然回到動畫姿勢IsGrounded 一翻 false，ikAllowed 立刻 false ⇒ 權重往 0 走①，刻意
站台階邊緣，骨盆沉下去了但角色看起來浮在邊緣膠囊高度不隨骨盆變動——IK 是純視覺層①③ 邊界，已定義的天花板
斜坡上 IsGrounded 一直 true，但某隻腳的 ray 沒打到東西② 是單點查詢，會落空；落空不代表沒接地②，刻意保留 ankle-only
「最終決定權」在誰手上
畫面上腳最後在哪裡，決定權在 Unity 的 Humanoid IK solver，不在我們。 我們給的是目標＋權重，solver 在腿長可達範圍內盡量靠近。 所以當你看到「腳沒有到我要的位置」時，先問的不是「Controller 算錯了嗎」， 而是「這個目標腿搆得到嗎」。
03

跨幀狀態：整個子系統只有四項

記憶盤點
跨幀的東西持有者為什麼需要跨幀弄丟會怎樣
四個權重FootIKTargetData權重必須平滑收斂，否則 IK 瞬切每次踩地／抬腳都跳變，腳彈一下
PelvisOffsetYFootIKTargetData骨盆瞬移比腳瞬移更明顯上下樓梯骨盆抽動
PoseData.IsWarmFootIKRig區分「全零是還沒寫過」與「真的是零」開場第一幀拿全零座標去打 raycast
FootPlantTracker ×2FootstepDetectorSchmitt trigger 的上膛／擊發狀態腳步聲在速度抖動時連發
📌 除此之外沒有任何跨幀記憶——而且腳的「位置目標」刻意不平滑
位置的連續性由「raycast 對連續地形連續」保證；台階邊緣的目標跳變由權重平滑吸收。 這是刻意的分工：平滑一個會瞬移的量，只會把瞬移變成滑移。

六條不能交換的順序

O1–O6
#約束交換之後會發生什麼
O1OnAnimatorIK 裡【出】必須在【入】之前output → input 反饋迴路 ⇒ 腳踝抽搐／腳黏地
O2Controller（順序 6.5）必須在 MotionDriver（順序 6）之後root 停在上一幀 ⇒ rootY 與 ray 原點落後一幀 ⇒ 高速移動時腳往後拖
O3Pipeline 必須「先驅動全部 controller，再發布事件」同幀 consumer 讀不讀得到，取決於 Hierarchy 誰被拖在上面
O4lift 先算出來，TargetPosition 與 GroundY 共用同一份兩邊各算一次會漂移——就是 §06 的 bug
O5骨盆補償在兩腳採樣之後、各腳解算之前骨盆要的是「兩腳的最低地面」，少一腳就不是最低
O6IK 結果一幀延遲不是順序問題，是結構（見上圖）
05

真實案例：X Bot 走上一道 12° 斜坡

實際 authored 值
// 這隻角色的常數（Avatar 量出來的，不是手填） FeetBottomHeight = 0.0873 膠囊 center=(0, 0.9134, 0) radius=0.32 height=1.8266 skinWidth=0.03 // FootIKSettings（X Bot.prefab 上實際序列化的值） RaycastUpOffset = 0.25 RaycastDistance = 0.85 HeelOffset = 0.025 ToeOffset = 0.17 ⇒ 跨距 0.195 MaxFootAlignAngle = 23° UseTwoPointSampling = true FootGroundedHeightMin = 0.08 FootGroundedHeightMax = 0.25 WeightSmoothSpeed = 8 MaxPelvisOffset = 0.35 PelvisSmoothSpeed = 5
// 第 1 步：先看平地 —— 答案是「IK 什麼都不做」 ray 原點 = goal + up×0.25 = y 0.3373，向下打 0.85 平地命中 y = 0，法線 = up ClampGroundNormal(up, 23°) ⇒ 夾角 0° ≤ 23° ⇒ 原樣回傳 ComputeAnkleTarget ⇒ 垂直 ray、水平分量≈0 ⇒ 退化分支 ⇒ target = hitPoint + up×0.0873 = (x, 0.0873, z) 這正好等於動畫 goal。 平地上 IK 目標與動畫目標重合 ⇒ 看不出任何差別。 這是正確的：IK 只有在「地面 ≠ 動畫假設的平面」時才有東西可修。
// 第 2 步：權重 —— 這裡有一個值得知道的細節 footHeightAboveRoot = 0.0873 − 0 = 0.0873 ComputeFootWeight(0.0873, min=0.08, max=0.25) = 1 − InverseLerp(0.08, 0.25, 0.0873) = 1 − (0.0073 / 0.17) = 0.957 ← 不是 1.0
⚠️ 一個可驗算的事實，不是猜測
FootGroundedHeightMin = 0.08 被設在這隻 Avatar 自己的腳踝高度 0.0873 下面 ⇒ 一隻「完美踩在地上、高度等於 bind pose」的腳，權重上限就是 0.957。
0.957 與 1.0 的視覺差極小，但它意味著這個門檻沒有留任何餘裕—— 動畫踩地相只要比 bind 高 1 公分，權重就掉到 0.90。 想讓踩地相確實吃到權重 1，FootGroundedHeightMin 應該 ≥ FeetBottomHeight。 本頁只陳述這個量測，不擅自改資產。
你現在應該能口頭講一次
「Rig 在 IK 套用前把動畫的腳 goal 拍下來。Controller 拿那個 goal 往上抬 25 公分打一條 ray 找地面， 把法線夾在踝關節 23 度以內，算出腳底貼住坡面時腳踝該在哪；再用腳跟腳尖兩條 ray 看腳掌有沒有戳進去， 有就整隻往上抬。兩腳都算完之後，骨盆沉到比較低的那隻腳，最多 35 公分。 權重看動畫腳離 root 平面多高——8 公分以下算踩地、25 公分以上算抬腳，中間線性，再平滑。 全部寫進 Target，下一幀 Rig 套給 Animator。角色站在哪、能不能跳，這整套一個字都沒碰。」
06

Failure case：斜坡上骨盆在兩態之間反覆跳動

2026-09-08 probe 確診

症狀：角色站在小斜坡上時，在「骨盆高／膝蓋直」與「骨盆低／膝蓋彎」兩態間反覆跳動。 平地完全正常。

階段這一層的行為是不是凶手
1 Animation Goalidle 動畫的腳部有細微位移❌ 正常（但它是觸發器）
2 Ground Observationprobe 證明 L.hit／R.hit 全程未翻動❌ 排除「raycast 間歇落空」
① Gameplay Groundedprobe 證明 IsGrounded／ikAllowed 全程未翻動❌ 排除「isGrounded 在斜坡跳動」
4 Heel/Toelift = max(0, max(heelPen, toePen))❌ max() 對輸入連續
4→5 交接GroundY = heelPen >= toePen ? heelHit.point.y : toeHit.point.y✅ 就是這裡
5 骨盆忠實地跟隨一個會跳的輸入❌ 它沒錯，它被餵了錯的東西
可推廣

I10：由「不連續選擇」導出的量，不得餵給被當成連續量使用的下游。 本 repo 已把它列為專屬記憶——看到「兩態之間反覆跳動」而且「退化情形下正常」， 先去找程式裡的硬分支，不要先懷疑環境或參數。

文件陷阱

docs/05 §3.5.4.1 用當時的預設值 0.1 + 0.15 = 0.25 推導跳幅， 推得坡度 9.5°～15.5°。那個數字現在是錯的——prefab 上 authored 的是 0.195。 重算必須用 0.195，別直接引用舊值。

07

權限表與不變量

改動前必讀
角色可以寫⛔ 絕對不可以
FootIKRigFootIKPoseData；Animator 的 SetIK*／bodyPosition打 raycast、讀黑板、判定 plant/lift、任何決策分支
FootIKControllerFootIKTargetData讀骨骼 Transform（反饋迴路）；寫黑板；寫 CharacterController；引用其他 Controller
FootstepDetector只有自己的 FootPlantTracker寫黑板（它回傳 struct）；從 Controller 取 Pose 引用
PresentationPipeline黑板 PresentationEvents 區（唯一 Writer）做輸出仲裁（目前刻意沒有）
MotionDriverIsGrounded／位置／落地事件碰任何 IK 資料
#不變量破壞的後果
I1Controller 的輸入只來自 FootIKPoseData，永不來自骨骼 Transform反饋迴路（O1）
I2每條管道恰好一個 Writer新增 Reader 時所有權錯置
I3新 Pose 讀取者向 owner 取引用，不向其他 Reader 要構成 Controller 互相引用
I4PelvisOffsetY ≤ 0（只沉不頂）上坡側把角色頂起來
I5lift ≥ 0（戳穿修正只向上）端點懸空時把腳往下壓 ⇒ 腳插進地裡
I6權重只經 MoveTowards 改變，永不直接賦值IK 瞬切，腳彈一下
I7Root 原點 ＝ 腳底平面 ＝ 膠囊底（ADR-001）權重門檻與骨盆補償同時失準
I8IK 不寫膠囊、不寫黑板、不改角色位置出現第二個接地／位置權威
I9額外資訊不足不是關 IK 的理由邊緣地形上 IK 整個閃爍
I10不連續選擇導出的量，不得餵給連續量下游§06 的 bug
