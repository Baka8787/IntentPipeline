Jump 與落地解剖

StateType.Jump 承載所有滯空時間——包含走下平台的自由落體， 那也叫 Jump。但這個 state 自己擁有的東西只有一組：時序與相位。 它不擁有位置、不擁有速度、不擁有接地真相。

02

六個相位與各自的位移路徑

只有一個相位不走 ExecuteBaseMovement
相位進入條件離開條件位移路徑
Windup 起跳前搖JumpRequested && IsGrounded_stageElapsedTime ≥ takeoffDelayExecuteBaseMovement（還在地上，正常走）
Airborne 上升ApplyJumpLaunch 注入初速重建的 v_y ≤ 0ExecuteBaseMovement（有完整空中控制）
Falling 下降上一列，或非主動失地_airborneTimer ≥ 0.15 && IsGrounded同上
Land / NormalStop落地、|v_y| ≤ 8、無移動意圖時間到，或出現新移動意圖（可提前結束）ExecuteBaseMovement
Land / NormalContinue落地、|v_y| ≤ 8、有移動意圖時間到（⛔ 不接受提前結束）ExecuteBaseMovement
Land / HardRecovery落地、|v_y| > 8時間到（⛔ 不接受提前結束）🔴 ExecuteVerticalOnlyMovement——沒有水平速度
🔴 Start → Falling 是物理條件，不是「動畫播完」
ShouldEnterFalling(...) 的簽名裡刻意沒有 clip duration。 它用 JumpState 自己擁有的拋體參數重建該時刻的垂直速度，≤ 0 就切 Falling。
這不是第二份物理狀態——函式無跨幀儲存、不寫黑板，只是讓動畫分類與 MotionDriver 接到的同一份 JumpLaunchData 保持同源。
⛔ 紅線

HardRecovery 的鎖定是「這一幀我不消費水平輸出」，不是「把水平輸出擦掉」。 不得藉由清空 MoveDirection 來達成鎖定——那會破壞黑板的單一寫入者契約。

真實案例：X Bot 站著按下跳躍

兩個獨立驗算
// Bake_Jump_place_ALL_short.asset（實測） AutoTakeoffDelay = 0.0873 s AutoApexHeight = 0.9535 m AutoAirTime = 0.6743 s AutoCalculatedGravity = 16.7770 m/s² // 第 1 步：Initialize 時逆推初速（只算一次） g = 16.7770 × GravityMultiplier(1) = 16.7770 h = 0.9535 × HeightMultiplier(1) = 0.9535 v = √(2gh) = √(2 × 16.7770 × 0.9535) = √31.994 = 5.6564 m/s // 驗算 ①：apex 自洽 apex = v²/(2g) = 31.994 / (2 × 16.7770) = 0.9535 m ✓ 逐字命中 AutoApexHeight // 驗算 ②：滯空時間 上升 = v/g = 5.6564 / 16.777 = 0.3372 s 下降對稱 = 0.3372 s 總滯空 = 0.6744 s vs bake 量到的 0.6743 s ← 差 0.1 毫秒
// 重落地的門檻在哪 —— 同一個 hardLandingSpeed，兩個不同的答案 hardLandingSpeed = 8 m/s 主動跳躍 落後重力 = 16.777（跳躍注入的） h = v²/(2g) = 64 / (2 × 16.777) = 1.907 m ⇒ 從比自己正常跳躍（0.95 m）更高兩倍的地方跳下來才算重落地 走下平台 非主動失地不注入任何 launch，_activeGravity 還原成預設 −9.81 h = 64 / (2 × 9.81) = 3.26 m
⚠️ 同一個門檻，主動跳躍 1.91 m 觸發、走下平台要 3.26 m
這是兩條路徑重力不同造成的，不是 bug，但它不是直覺的。 要改的話動的是重力來源，不是門檻。

Failure case ①：重落地永遠判不出來

發布時機決定語意

症狀：從很高的地方跳下來，播的還是普通落地動畫，沒有 recovery 鎖定。

05

Failure case ②：空中被打完全沒有受擊反應

一個 authored 空清單

症狀：角色在空中被敵人打到，血扣了，但完全沒有受擊動畫。

階段這一層是不是凶手
傷害結算CharacterHealth 在 Physics 階段結算，順序 0.5 發布到黑板❌ 正常
HurtState.CanEnter讀 Survivability.JustTookDamage ⇒ true❌ 它想進來
EvaluateInterrupts_currentState.CanBeInterruptedBy(Hurt) ⇒ 查 config🔴 就是這裡
config 資產Jump 的 CanBeInterruptedBy 是空清單✅ 根因
根因不在程式裡，在資產裡
PlayerStateMachineConfig.asset 的 Jump 規則現在是 CanBeInterruptedBy = [Hurt(8), Death(7)]——但它曾經是空的。 清空可打斷清單 ⇒ 空中連死都死不了。
這類缺陷 grep 程式碼永遠找不到，因為程式完全正確地執行了一份空清單。
可推廣

「某個功能從來沒觸發過」時，先問它的 gate 是不是資料。 本頁兩個 failure case 都屬這一類：一個是發布順序，一個是 authored 空清單—— 兩個都不會有錯誤訊息，也都不會讓任何測試變紅。

06

跨幀狀態：十一項

全部不進黑板
跨幀的東西持有者弄丟會怎樣
_verticalVelocity／_activeGravity
_gravityFrame／_cachedGravity		MotionDriver一幀被積分兩次 ⇒ 重力加倍
_wasGroundedMotionDriver落地音效不響或連響
_jumpIndexJumpState無限空中跳
_isVelocityInjectedJumpState每幀注入 ⇒ 飛天
_stageElapsedTimeJumpState前搖失效，動畫與物理不同步
_airborneTimerJumpState離地當幀就被判成落地
_ungroundedSinceJumpState斜坡上的 isGrounded 抖動被誤判成掉下去
_enteredFromFallJumpState重新打開 ADR-002 已封住的無限空中跳
_takeoffTier／_takeoffFootPhaseJumpState用 Run 起跳、用 Idle 落地
_landingPhase／_landElapsedTime
_landDuration		JumpStateHardRecovery 沒有鎖定效果

「跳多高是從動畫量出來的——apex 0.95 公尺、重力 16.78，逆推出初速 5.66。 按下跳躍先前搖 0.087 秒，這段還在地上正常走；然後注入初速，上升 0.337 秒到頂， 對稱落下。切 Falling 的條件是重建出來的垂直速度 ≤ 0，不是動畫播完。 落地時看撞地速度分三類，超過 8 m/s 就進 HardRecovery，那一相位不消費水平輸出。 整個過程 JumpState 只管時序與相位，位置與速度都是 MotionDriver 的。」
