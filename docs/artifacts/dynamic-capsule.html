這張圖跟一般的方塊圖差別在：每條箭頭都標了四件事—— 資料是什麼、誰擁有它、多久更新一次、以及它是不是跨幀記憶。 箭頭沒有這四項，就只是「有關係」，不是架構。

Authority：誰可以動膠囊，什麼時候

共用可變狀態

CharacterController 的 center／radius／height 是共用可變狀態。 三個角色想動它——所以必須講清楚誰、在什麼時候、有權力動哪一個欄位。 「什麼時候」這一欄是多數架構圖會漏掉的維度。

角色可以寫不可以寫什麼時候
Authored geometry—任何東西（它是常數）永遠
Pose offsetcenter.x / center.zcenter.y、radius、heighttraversal 沒在跑、功能開著、沒死
Traversal profilecenter / height / radius 全部—只在一次 traversal 執行期間
🔴 為什麼 center.y 不准動
改變膠囊底面高度，就改變了 Unity 判斷「有沒有踩到地」的結果。 而 FootIKController 的開關是二值、沒有淡入的——判斷錯一次，玩家就會看到腳彈一下。 所以本輪把 center.y 完全排除在外。膠囊高度確實是個真問題，但那是另一個決定。
恢復陷阱

traversal 結束時會把 center 還原成「它開始前記下的值」。若那個值裡混進了姿勢偏移， 還原之後偏移就變成永久的——而那時 traversal 已經結束，沒有任何人會把它改回來。 所以 BeginTraversalCollisionProfile 的第一件事，是把姿勢偏移收乾淨再記基準。

03

跨幀狀態：整個子系統只有一個

記憶盤點

要判斷一個系統好不好推理，最快的方法是問：它記得多少事？ 每一個跨幀狀態都是一個可能不同步、可能該重置而沒重置、可能在切場景時殘留的點。

跨幀的東西持有者為什麼需要跨幀弄丟會怎樣
SmoothedOffset MotionDriver 偏移必須連續變化，否則膠囊瞬移 每幀跳變，貼牆判定忽大忽小

就這一個。其餘全部每幀重算：landmark 每幀取樣、solver 每幀重解、cast 每幀重打、cap 是純函式。

Failure case：舊模型在沒問題的地方製造了 15 公分的問題

V1 → V2

V1 的模型是 offset = normalize(MoveDirection) × MaxOffset × speed—— 白話是「角色往哪走，膠囊就往哪偏」。聽起來很合理，實測錯得很離譜。

可推廣

這是一個量測代理不對題的典型：用「角色往哪移動」去代理「身體往哪傾」。 兩者在前進時剛好相關，在側移時完全無關——而它在相關的那一段給得太少、在無關的那一段給得太多。 代理量的可信區間比它的平均誤差重要。

殘留

MoveDirection 在 V2 只剩一個用途：Scene view 的 gizmo 會把舊模型的目標畫成紅色虛線， 讓你親眼看到它指向哪裡。它不參與任何計算。
