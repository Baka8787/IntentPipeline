骨盆高度統一模型：盤點與離線比較

樓梯移動中的身體高度，從「一直維持每步最壞時刻」改成「意圖 → 可達約束 → 連續求解」。本頁是 docs/46-pelvis-body-height.md 的圖解版，數字以該檔為準。

⛔ runtime 未改只量測／離線模擬stop 規則未碰L = 0.889 m · Leg Stretch 1.05 L

三個結論

20–25 cm／步

字面的 B 與 C 都不可行

「只在需要時下降」若回升不受限，每一步都回到名目高度再降下。上樓逐步起伏 20–25 cm、骨盆加速度是包絡的 7 倍。

+6～10 cm

包絡的深度多半是平順的代價

可達需求每步振盪約 20 cm。完美預知、加速度 ≤ 4 m/s² 的 oracle 也只比包絡高 6–10 cm。

+6～8 cm

統一模型 R 全面不輸包絡

Walk 下樓每一項都更好；Walk 上樓搆不到 3.8% → 0%；Run 上樓 15% → 3.8%。代價：Walk 上樓髖加速度 p95 15.5 → 18.7–23.4 m/s²。

哪些腳該約束骨盆

每隻腳每帧算全腿長可達上限，依 T3 相位分類。上樓的深度來自仍在支撐期的後腳，下樓來自即將落在下一階的前腳。只看 Locked 腳時，一半的帧完全不需要下沉。

Support · 約束T3 Locked 且動畫仍在支撐期。後腳用前掌支點（允許抬跟 ≤ 35°）算最寬鬆放置。上樓時最緊約束 37–47% 的帧。
Landing · 預告約束未鎖且目標腳底正在下降。上限 B + κ·h，接觸瞬間精確。下樓時最緊約束 22–38% 的帧。
Releasing · 不約束腳正在離地，T3 只是把目標留在鎖定點防滑。上樓時它會要求 −30 到 −72 cm。
Swing · 不約束在空中，搆不到只是擺盪腳略短，沒有接觸後果。

移除一條上限只會讓骨盆放鬆，不會迫使它下跳；只有加入上限可能迫使下降。所以落地時的加入由 Landing 的連續預告負責，不需要 fade 或 gate。
