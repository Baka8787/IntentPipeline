這頁是索引，不是教材。 它只做兩件事：給你一張全域座標系，然後告訴你深度在哪一頁。

同一件事有兩份說明，遲早會漂移成兩份不一樣的說明——而且你不會知道哪一份是對的。 子系統架構頁出現之後，這頁再留一份淺版就不是「方便」，是負債。

L2

尚無子系統架構頁的子系統

暫住在這裡

這四張留在索引頁，不是因為它們比較不重要，而是因為它們還沒有對應的 docs/NN-architecture-guide 文字正本。 沒有正本就做子系統架構頁，等於在發明內容而不是視覺化既有結論——所以它們暫時維持索引層的深度。
⚠️ 這四張只有「為什麼／否決了什麼／哪條測試守著」，沒有資料契約表、authority 時間軸與數值驗算。

目前基線與尚未完成的邊界

項目狀態意思
ADR-005 多 ActionAccepted三技能、per-slot 冷卻、Reaction 保留段、Play 與 Profiler 驗收已完成。細節見 action-combat.html。
ADR-007 Direction AuthorityTrialS1／S2／S3／F6 已落地：世界移動方向、ActionReleaseContext、唯一 CharacterFacingSource、IAimSource seam。A28–A32 已守住，但 ADR 尚未翻 Accepted。
ADR-006 上半身層TrialSpell＝Layer 1 upper-body mask；Layer 0 使用 Walk／Run 雙 8-way ring。Sprint directional presentation 延後。待 Play 驗收。
ADR-008 TraversalTrialProbe→Selection→Fitting→Plan→root warp→Contact→Hand IK 已接通，Vault1m／Climb1m／Climb2m 三支都已啟用。🔄 D10（2026-09-21）新增第二種 execution model Segmented，committed 的定義改述為「landmarks／timing／contact targets 固定」而非「絕對軌跡固定」——Climb2m 走這條，另兩支不變。自動測試已達成 Acceptance Criteria；人工 Play 的視覺驗收仍未進行。細節見 traversal.html §06。
Action targeting已實作CameraForward 為預設；只有顯式 CameraConeSoftTarget 才會在角錐內使用 CombatContext target。不是 persistent lock-on。
MAP Jump ＋ Walk-off Falling已驗收主動跳與非主動失地共用 JumpState；落地分類統一讀 VerticalVelocity。EditMode／PlayMode 全綠。
Foot IK 斜坡抽搐已修正已證實為 GroundY 不連續並改由實際腳底平面導出；連續性測試留存。追因過程見 failure-atlas.html。
Persistent lock-on／正式 8-way未實作現有 RunRing／FullRing 僅是量測 prototype。CombatContext 不等於 lock-on。
敵人 AI已實作只有一顆 AIMovementSource（距離帶＋遲滯）。它證明的是介面可換，不是「有 AI 系統」。
Footstep＋Surface已實作八個偵測參數全部來自對真實動畫的量測；材質五層優先級 ＋ per-foot 記憶化。FootstepKind.Shuffle 已無 runtime producer。細節見 footstep-surface.html。
Presentation Audio已實作程式與接線完整；素材刻意不完整（13 個 Combat 池只有 3 個有 clip，使用者裁決「不為了有聲音硬塞」）。細節見 presentation-audio.html。
Upper Body Layer（ADR-006）DEFERADR 仍 Trial 且待 Play 驗收；缺 architecture-guide 級文字正本。
Editor Bake Toolchain另一類4,545 行但形狀不同（資產生產管線，非執行期 authority）。保留為未來的 Authoring Pipeline / Toolchain Architecture，⛔ 不硬套 Subsystem Architecture 格式。
Grounding、HeadLook不獨立成頁Grounding 的 runtime 實驗已全數撤回，其 authority 已由 foot-ik／authority-timeline／jump-landing 三頁涵蓋；HeadLook 是 CombatContext 的消費者實例。
網路／存檔／UI 框架—不在 scope。被問到就直接這樣說。
